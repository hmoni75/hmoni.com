# Repository Guidelines

## Project Structure & Module Organization

This repository is a Vite-powered React site written in TypeScript. The active application lives in `src/`: route-level views are in `src/pages/`, reusable UI and effects in `src/shared/`, page shells in `src/layouts/`, SEO helpers in `src/seo/`, and API access in `src/services/`. `src/extra/` holds additional page variants and shared components; it is excluded from the configured TypeScript project (`tsconfig.json`). Static assets and browser scripts are under `public/`, while `dist/` is generated by builds and should not be edited by hand.

## Build, Test, and Development Commands

- `npm install` installs dependencies from the lockfile.
- `npm run dev` starts the local Vite development server.
- `npm run build` creates the production site in `dist/`.
- `npm run preview` serves the production build locally.
- `npm run lint` runs ESLint across the repository; `npm run lint:fix` applies automatic fixes.

There is no dedicated test script or test suite configured. Run lint and a production build when validating a change.

## Coding Style & Naming Conventions

Use TypeScript and React function components. Follow the surrounding file's formatting; use two-space indentation and double quotes, consistent with the project configuration and existing code. Name React component files and components in PascalCase (for example, `ContactPage.tsx` and `ContactPage`); use descriptive camelCase for hooks and utilities (for example, `useHeaderInteractive`). Keep reusable UI in `src/shared/` and page-specific composition in the relevant page file. ESLint enforces TypeScript and React Hooks rules; unused variables prefixed with `_` are ignored.

## Testing Guidelines

No unit or integration test framework is configured. For UI changes, run `npm run lint` and `npm run build`, then manually check affected routes in the dev server, including responsive behavior when relevant. Fix newly introduced lint or build errors before submitting.

## Commit & Pull Request Guidelines

Recent commits use short, imperative descriptions, such as `update contact phone numbers to new format`; keep commit subjects concise and focused. Pull requests should explain the user-visible change, list affected routes or components, and include screenshots for visual changes. Note the validation commands you ran and link a related issue when one exists.

## Security & Configuration

Keep credentials and environment-specific values out of committed source. Treat files in `public/` as publicly served assets. Review changes to `vite.config.ts`, `vercel.json`, and the database population scripts carefully because they affect deployment or remote data access.
